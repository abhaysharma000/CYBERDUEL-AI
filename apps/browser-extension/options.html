Security Architecture & Permissions Onboarding

Complete transparency on extension capabilities, bounds, and limitations.

Declared Permissions and Justifications

  • storage: Persists the verified policy bundle, cryptographic manifest metadata, monotonic sequence counter, and user settings securely in chrome.storage.local.
  • declarativeNetRequest: Compiles approved threat indicators into synchronous browser dynamic blocking rules. Runs directly inside the browser network process with zero overhead.
  • alarms: Schedules periodic background checks (default every 30 minutes) to query the release authority for signed security updates without running a permanent background process.
  • activeTab: Enables the popup to query the active tab's URL for on-demand manual security inspection without requiring permanent tab monitoring.
  • host_permissions (<all_urls>): Required for the Declarative Net Request engine to block confirmed malicious domains across the web and for the Link Guard content script to intercept clicked phishing links.

Known Protection Boundaries

CyberDuel AI explicitly acknowledges the boundaries of browser-based security:

  • Typed Navigation: Manifest V3 does not allow arbitrary extensions to synchronously inspect URLs typed directly into the omnibox before navigation, unless matched by existing declarative DNR rules.
  • Dynamic Quotas: Chrome enforces a strict limit (~30,000 rules) on dynamic declarative rules. CyberDuel optimizes this by compiling only high-impact confirmed indicators into DNR.
  • No Arbitrary Code in Updates: Update bundles contain strictly declarative AST rules, prefixes, and weights. No remote JavaScript, WebAssembly bytecode, or scripts are ever downloaded or executed.
